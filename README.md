# SIMPOTEL — AI Hotel Guest Assistant

A full-stack AI-powered hotel guest assistant built for the Simplotel assignment. Guests can ask questions about the hotel and check mock room availability through a conversational React interface.

## Project overview

The application demonstrates a practical split between deterministic hotel business logic and LLM-powered natural-language conversation.

- **Frontend:** React + Vite
- **Backend:** FastAPI + Python
- **AI:** Google Gemini via `google-genai`
- **Hotel knowledge:** JSON knowledge base
- **Availability:** deterministic mock availability service
- **Testing:** Pytest + FastAPI TestClient
- **Deployment target:** Vercel for the frontend and backend

## Customer problem

Hotel guests often need quick answers about check-in/out, amenities, breakfast, cancellation policies, suitable rooms, and availability. The assistant provides a single conversational interface instead of requiring guests to search through multiple hotel pages.

## Guest journey

1. Guest opens the assistant.
2. Guest asks a hotel question.
3. Backend checks deterministic hotel knowledge first.
4. If the knowledge base cannot answer, Gemini receives the hotel context and conversation history.
5. For room availability, deterministic backend logic collects dates/guest count and calculates suitable mock room options.
6. The UI displays the answer, loading state, errors, or availability results.

## Why deterministic logic + AI?

Hotel facts and availability should not be invented by an LLM. The backend therefore handles known facts and business rules deterministically wherever possible. Gemini is used for natural-language questions, follow-ups, and conversational understanding while being explicitly instructed to use only the supplied hotel context.

### Deterministic flows

- Check-in time
- Check-out time
- Hotel location/address
- Amenities
- Breakfast policy
- Cancellation policy
- Room suitability by guest count
- Availability request flow
- Date/guest validation
- Mock availability calculation

### Gemini flows

- Natural-language questions not directly matched by the deterministic knowledge base
- Follow-up questions using conversation context
- Conversational phrasing of grounded hotel information

### Hallucination prevention

- Hotel facts come from `backend/data/hotel.json`.
- Availability is never generated by Gemini.
- Gemini is instructed not to invent hotel facts, prices, policies, facilities, or availability.
- Unsupported facility-condition questions such as maintenance/cleanliness are explicitly returned as unknown when the knowledge base has no such information.
- AI/API failures have a user-safe fallback response.

## API

### `GET /`
Returns a basic API status message.

### `GET /health`
Returns:

```json
{"status":"healthy"}
```

### `POST /chat`

Request:

```json
{
  "message": "What time is check-in?",
  "conversation": []
}
```

Response shape:

```json
{
  "message": "Check-in is at 2:00 PM.",
  "source": "hotel_knowledge_base",
  "needs_availability": false,
  "handled": true
}
```

### `POST /availability`

Request:

```json
{
  "check_in": "2026-09-20",
  "check_out": "2026-09-22",
  "adults": 3
}
```

The service validates dates and guest count, finds rooms whose capacity is sufficient, and calculates the total mock stay price.

## Error handling

- Invalid availability dates return HTTP 400.
- Invalid guest count returns HTTP 400.
- Unexpected backend failures return a controlled HTTP 500 response for availability.
- Chat processing failures return a safe fallback message.
- Missing/failed Gemini access does not expose internal errors to guests.
- Frontend network failures show a user-facing error state.

## Evaluation / demo scenarios

### Normal question

> What time is check-in?

Expected: deterministic hotel knowledge response.

### Follow-up / context

> Does the hotel have a swimming pool?
>
> Is it free for guests?

The second question is not answered with an invented fee because the fee is not present in the hotel knowledge base.

### Unsupported assumption

> Is the swimming pool maintained properly?

Expected: the assistant states that maintenance/condition information is not available rather than assuming the pool is maintained properly.

### Availability

> I need a room for 3 adults.

Expected: the assistant opens the availability flow requesting dates and guest count.

### Frontend/backend failure

Stop the FastAPI server and submit a chat message. The frontend should display a connection error rather than silently failing.

## Product and UX decisions

- Conversational interface keeps the main guest journey simple.
- Quick suggestion buttons reduce typing for common questions.
- Dedicated availability form makes dates and guest count explicit.
- Loading indicators communicate that an AI/API request is in progress.
- API errors are shown in the UI.
- Availability results show room capacity, nightly price, nights, and total price.
- Responsive layout supports desktop and mobile use.

## What could go wrong?

- Gemini API unavailable or rate-limited
- Incorrect or incomplete hotel knowledge
- User asks about information that is not in the knowledge base
- Backend unavailable
- Invalid dates or guest count
- Ambiguous follow-up questions

## Local setup

### Backend

```powershell
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Set your Gemini key in `backend/.env`:

```env
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

Run:

```powershell
uvicorn main:app --reload
```

Backend: `http://127.0.0.1:8000`
Docs: `http://127.0.0.1:8000/docs`

### Frontend

```powershell
cd frontend
npm install
npm run dev
```

For local development, `frontend/.env` can contain:

```env
VITE_API_URL=http://127.0.0.1:8000
```

## Vercel deployment

Deploy the two applications as separate Vercel projects from this repository.

### Frontend project

- Import `lohitsai-analytics/SIMPOTEL`.
- Set **Root Directory** to `frontend`.
- Framework/preset: Vite.
- Build command: `npm run build`.
- Add environment variable:

```env
VITE_API_URL=https://YOUR-BACKEND-VERCEL-DOMAIN
```

### Backend project

- Import the same repository as a second Vercel project.
- Set **Root Directory** to `backend`.
- Python/FastAPI entry point: `main.py` / `app`.
- Add environment variable:

```env
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
```

- After the frontend has a Vercel URL, add:

```env
FRONTEND_URL=https://YOUR-FRONTEND-VERCEL-DOMAIN
```

The backend uses `FRONTEND_URL` to allow the deployed frontend through CORS while retaining the local development origins.

**Never commit a real `.env` file or Gemini API key.**
